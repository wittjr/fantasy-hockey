## Spacing Scale

Same scale as Phase 1 (multiples of 4: 4, 8, 16, 24, 32, 48, 64), applied through Tailwind units.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between squares (`gap-1`), row vertical padding (`py-1`), tag/tab vertical padding, popover offset (`mt-1`), selected-row bar width |
| sm | 8px | Popover padding (`p-2`), first-column left padding in the trends table (`pl-2`), gap between header stats' label and value |
| md | 16px | Panel padding (`p-4`), gap between panel children (`gap-4`) |
| lg | 24px | Gap between header stats (`gap-x-6`) |
| xl | 32px | Page-level `gap-8` between sections (existing) |
| 2xl / 3xl | 48 / 64px | not used |

Exceptions (all intentional):
- **Heat-strip squares: 20x20px (`h-5 w-5`), 4px gap (`gap-1`), 2px corners (`rounded-xs`), 1px border on every square**, identical to Phase 1. Rows use `py-1`, so the vertical gap between squares is 8px; the horizontal pitch is 24px (WCAG 2.5.8).
- **12px** tab/column gutter (`px-3`, `pr-3`): already used by the page; a multiple of 4.
- **Hairlines**: 1px borders, 2px focus outline and `outline-offset-2`, 2px F/D divider (`border-t-2`), 2px tab underline (`border-b-2`). Not spacing.
- **Popover clearance 112px** (`pb-28 -mb-24` on the table scroll wrapper), the same Phase 1 value, so a downward popover on the last row is not clipped by `overflow-x-auto`. (IN-05: still a fixed number; the heat strip has at most about 10 rows, fewer than the trends table, so the Phase 1 headroom is sufficient.)
- **Header month label** sits above the day number in a 16px line each; no new spacing token.

## Color

Neutral palette matching the page. No brand accent. Phase 2 adds **no new colors**: it reuses Phase 1's green/red mover pair, the amber caution color, and the sky OT marker.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#ffffff` / `#0a0a0a` | Page surface, panel interior |
| Secondary (30%) | `neutral-200/800` panel border, tab rule and header rule; `neutral-100/900` row rules; `neutral-300/700` F/D divider and square borders; `white` / `neutral-900` popover surface; `neutral-500` header text; `neutral-600` / `neutral-400` muted text | Panel chrome, table chrome, popover, muted text |
| Accent (10%) | green `green-700` / `green-400`, red `red-700` / `red-400`; tint `green-100` / `green-900/40`, `red-100` / `red-900/40` | Directional movers only (list below) |
| Caution | `amber-600` / `amber-400` | Missing-shift-chart: dashed border on unknown cells, and the footnote text |
| Informational | `sky-500` | OT only: `ring-1 ring-sky-500` on OT-game cells, the `OT` tag in the popover |
| Destructive | not applicable | No destructive actions |

**Accent reserved for (explicit list, extends Phase 1 and adds one item):**
1. The TOI Δ and PP share Δ numbers in the **panel header stats** when they cross the Phase 1 thresholds (`|TOI Δ| >= 120 s`, `|PP share Δ| >= 15` points): `font-medium text-green-700 dark:text-green-400` or `text-red-700 dark:text-red-400`. Same helper as `DeltaCell` (`deltaCrossing`).
2. The existing trends-table Δ numbers and row tint (Phase 1, unchanged).

Nothing else in Phase 2 is green or red. In particular **the New / Rising / Fading / Out tags are neutral** (discretion). Rationale: Rising/Fading describe time together, not linemate quality (PLYR-04, and quality scoring is out of scope), and green/red would read as "good/bad linemate". This follows the Phase 1 precedent that trend arrows are always muted neutral. The tags are told apart by glyph, fill and border style, not hue.

**Heat-strip cell fill (neutral ink, like Phase 1 strip cells):** `bg-neutral-800 dark:bg-neutral-200` on an inner element with inline `style={{ opacity }}`, so the popover child is never faded.

`opacity = 0.2 + 0.8 * clamp(share / LINEMATE_SHADE_SATURATION_SHARE, 0, 1)` where `share` = seconds together ÷ the selected player's regulation seconds in that situation that game (D-08), and `LINEMATE_SHADE_SATURATION_SHARE = 0.75` (named constant, **discretion**). A linemate on the ice for 75% or more of the player's time in that situation is fully dark; the 0.2 floor keeps any real time visibly "filled" and distinct from a hollow square. The scale is absolute, not per-row or per-player, so shades compare across rows and games. A 15-point share change (the tag threshold) is a 0.16 opacity step, clearly visible. Shade is redundant with the popover (exact values), so it is exempt from 3:1 non-text contrast, as in Phase 1.

**Cell states (the heat strip's full vocabulary; every cell is a 20x20 bordered square):**

| State (`data-state`) | When | Visual |
|----------------------|------|--------|
| `together` | Both played, shift data, `seconds > 0` | Neutral fill by the opacity formula; solid `border-neutral-300 dark:border-neutral-700`. OT game: add `ring-1 ring-sky-500` (regulation seconds only, D-19). |
| `apart` | Both played, shift data, the player had situation time that game, `seconds = 0` | No fill; solid `border-neutral-200 dark:border-neutral-800`. A real zero, drawn hollow so it differs from missing data. OT game: sky ring. Counts toward share and tags. |
| `absent` | The selected player or the linemate did not dress, or the linemate was not on the team (D-17, D-18, D-20), **or** the selected player had no time in this situation that game (share undefined) | No fill; dashed `border-dashed border-neutral-400 dark:border-neutral-600` (same as Phase 1 DNP). Never 0; left out of shares and tags. |
| `unknown` | The game has no shift chart (unpublished or failed request, D-24) | No fill; dashed `border-dashed border-amber-600 dark:border-amber-400`. Left out of shares and tags. |

Hollow/solid versus dashed carries the meaning without relying on hue; amber only separates "no data" from "did not play" within the dashed family.

**Text contrast:** all body text on the panel is on the plain page surface (no tint), so Phase 1's WR-09 concern (muted text on green/red-100 rows) applies only to the trends-table row where the new name link and selected-row bar are added. Rules there: link text stays the default foreground (not `neutral-500`); the selected-row bar is `neutral-900`/`neutral-100` (>= 3:1 against both tints); muted text in tinted rows stays `neutral-600` / `dark:neutral-400` (>= 4.5:1). Tag chips: "New" is `text-white` on `neutral-900` (about 17:1) and `text-neutral-900` on `neutral-100` in dark; other chips use `neutral-900/100` or `neutral-600/400` text on the plain surface (>= 5.7:1).

## Layout & Columns

### Page placement (D-01, D-03)

`app/research/page.tsx` renders the panel as the **first content section** under the team and window navigation, above `LastGameLines` and `ToiTrends`, only when `?player` is valid. "Top of the page" (D-01) is read as: above everything below the nav, so the jump (D-03) always lands at one fixed spot whether the click came from the trends table or a Last game unit table. If the selected player is not in the loaded roster for the window, render a one-line notice instead (see States).

### Panel structure

**Primary visual anchor:** the player name heading (`h2`, `font-medium`) and the `Avg TOI` value beside it identify the panel; the heat strip is the primary content below the tabs.

`<section id="player-detail" aria-labelledby="player-detail-title" className="scroll-mt-4 flex flex-col gap-4 rounded-md border border-neutral-200 p-4 dark:border-neutral-800">`

1. **Header row** (`flex flex-wrap items-start justify-between gap-x-6 gap-y-2`):
   - Left: `<h2 id="player-detail-title" className="font-medium">{name}</h2>` followed by `<span className="text-xs tabular-nums text-neutral-600 dark:text-neutral-400">{position} {gamesPlayed}/{teamGames} GP</span>` (the Phase 1 Pos string, e.g. `C 5/5 GP`).
   - Right: close link `PendingLink` `× Close player detail` (see Interaction).
2. **Header stats** (D-05): `<dl className="flex flex-wrap gap-x-6 gap-y-1">`, four items in the trends order: `Avg TOI`, `TOI Δ`, `PP share`, `PP share Δ`. Each item: `<dt className="text-xs text-neutral-600 dark:text-neutral-400">` label above `<dd className="text-sm tabular-nums">` value. Values come from the selected player's `TrendRow` with the same formatters as the table (`formatClock`, `formatSignedClock`, `Math.round(ppShare)%`, `formatSignedPoints`). Avg TOI is `font-medium`. A crossing Δ is colored per the accent rule plus `sr-only` "Moving up"/"Moving down". Unknown values render `—` (`text-neutral-400 dark:text-neutral-500`), never `0:00` or `0%`. **Window of 1:** drop the two Δ items (Phase 1 D-08). No slope arrows and no row tint in the panel.
3. **Situation tabs** (D-10): see Interaction.
4. **Intro paragraph** (`text-sm text-neutral-500`, copy below).
5. **Heat strip** (or an empty/no-data message), inside `<div className="overflow-x-auto pb-28 -mb-24">`.
6. **Show-all line** when the list is capped.
7. **Footnotes** (`flex flex-col gap-1 text-xs text-neutral-500`): legend lines, then the amber note and any tag note.

### Heat-strip table

`<table className="w-full text-sm">`. Header row `border-b border-neutral-200 text-left text-xs text-neutral-500 dark:border-neutral-800`. Body rows `border-b border-neutral-100 dark:border-neutral-900`. All cells `py-1 pr-3 whitespace-nowrap`.

| # | Header | Align | Cell content |
|---|--------|-------|--------------|
| 1 | Linemate | left | Linemate name. Plain text (no link in this phase; names only, D-23 and the no-quality rule). |
| 2 | (games) | left | Visually-hidden `<span className="sr-only">Games, oldest to newest</span>` plus the game-label row (below). Body cells hold the strip. |
| 3 | Window share | right | `Math.round(windowShare * 100)%`, `tabular-nums`; `—` when the player has no counted games or no situation time (D-09) |
| 4 | Tag | left | Tag chip or empty (see Tags) |

Column 4 and the tag logic are **hidden when the window is 1 game** (D-15, no tags). Columns 1-3 remain.

**Game-label row (column 2 header):** a `<div className="flex gap-1">` of one `w-5` item per team game in the window, oldest left, the same count, order and width as the body strips so labels line up with squares. Each item is two 16px lines, centered, `text-xs tabular-nums font-normal`: line 1 the month abbreviation (`Oct`) **only on the first game and where the month changes**, otherwise an empty line; line 2 the day of month (`8`). Built from the existing `formatDate`. The full `Oct 8 vs TOR` label is in each cell's popover and `aria-label`. The month text is 22px wide in a 24px pitch and never sits next to another month label.

**Group blocks (D-13):** two `<tbody>`s sharing the same columns. Each begins with a label row `<tr><th scope="rowgroup" colSpan={4} className="pt-2 pb-1 text-left text-xs font-medium text-neutral-500">Forwards</th></tr>` and `Defense` for the second. The Defense label row carries the F/D divider `border-t-2 border-t-neutral-300 dark:border-t-neutral-700`. A group with no listed linemates renders one row `None` (`text-neutral-500`, like `UnitTable`). The forwards block is always first.

**Linemate strip (column 2 body):** `<div role="group" aria-label="Games with {linemate}, oldest to newest" className="flex gap-1">` containing one `ToiStripCell` per team game, same order as the labels.

**Caps and minimums (D-11, discretion; named constants, tune on real data):**

| Situation | Forwards shown | Defense shown | Minimum time together in the window to be listed |
|-----------|----------------|---------------|--------------------------------------------------|
| EV | 6 | 4 | `2:00` |
| PP | 4 | 3 | `0:30` |
| SH | 4 | 3 | `0:30` |

Order is window share, highest first, then window total (D-28, superseding D-12's recent-first order), applied before the cap. `?all=1` lifts the cap but never the minimum.

### Trends-table changes (D-02, D-06)

- **Name cell:** the player name becomes a `PlayerLink` (see Interaction). Everything after it in the cell (the `sr-only` mover text, the `DNP last 2` chip) is unchanged.
- **First column padding:** every first-column cell, header and body, gets `pl-2` so the selected-row bar never touches the name and the name does not shift when a row is selected.
- **Selected row (D-06):** the selected player's first `<td>` gets a 4px neutral bar drawn as an inset shadow, `shadow-[inset_4px_0_0_0] shadow-neutral-900 dark:shadow-neutral-100`, and the name link gets `font-medium`. The row's green/red tint is untouched (the bar is neutral and sits on the left edge, so it never clashes). The link carries `aria-current="true"` and the cell gets `<span className="sr-only">Selected</span>`.

### Last game unit tables (UNIT-04)

In `UnitTable`, each name in the joined list becomes a `PlayerLink` carrying that table's situation as `sit`; the existing ` – ` separators stay as `aria-hidden` text. Goalies never appear in unit tables, so no goalie link exists. The table's own `sit` is passed in (`ev`, `pp`, `sh`). The selected player's name is `font-medium` with `aria-current="true"` wherever it appears.

## Interaction Contract

### Selecting a player (PLYR-01, UNIT-04, D-02, D-03, D-04)

- `PlayerLink` is a `PendingLink` (spinner slot, `prefetch={false}`) with the default `scroll` behavior (**not** `scroll={false}`). Its href ends in `#player-detail`, so Next scrolls to the panel after the server render. The jump is a **backstop check** (see UI Considerations): confirm in a browser that a click on a far-down row lands on the panel under the existing nav, including when the same player is re-clicked.
- Link look (so it reads as a link without noise): default foreground text with `underline decoration-neutral-300 underline-offset-2 hover:decoration-neutral-900 dark:decoration-neutral-600 dark:hover:decoration-neutral-100`; `focus-visible` uses the browser default ring. `title="Show who {name} plays with"` in the trends table and `title="Show who {name} plays with at {EV|PP|SH}"` in unit tables.
- Clicking a different name swaps the player. Back and forward restore the previous player and tab because both live in the URL.
- Clicking the selected player's own name is allowed and a no-op that re-jumps to the panel.

### URL contract (extends `researchHref`)

| Param | Values | Default (omitted) | Notes |
|-------|--------|-------------------|-------|
| `player` | NHL player id, digits only, must be a skater in the loaded roster for the window | absent | Invalid format: ignored silently, no panel. Valid format but not in the window: notice (States). Never reaches a fetch path. |
| `sit` | `ev` \| `pp` \| `sh` (allowlist, like `sort`) | `ev` | Invalid or array: `ev`. |
| `all` | `1` | absent | Lifts the list cap. Any other value: capped. |

- Existing `team`, `games`, `sort`, `dir` are kept by every link in the panel and by name links (D-04). `researchHref(team, games, sort, extras?)` takes `{ player, sit, all }` and omits defaults; hrefs are built only from validated values (T-01-06/T-01-07).
- **Team links** in the page nav drop `player` and `all` and keep `sit`. **Window links** (`Last game`, `Last 3`, ...) keep `player`, `sit` and drop `all` (discretion; this answers the open CONTEXT item: the player is dropped on a team change, kept on a window change, and a window that does not contain him shows the notice). **Sort header links** keep `player`, `sit` and `all`.
- The hash `#player-detail` is appended only to name links. Tab, close, show-all and sort links use `scroll={false}`.

### Situation tabs (D-10)

- `<nav aria-label="Situation" className="flex gap-1 border-b border-neutral-200 dark:border-neutral-800">` with three `PendingLink`s `EV`, `PP`, `SH` in that order, `scroll={false}`, each carrying the full current URL with `sit` set (omitted for `ev`). These are links that change URL state, so they use `aria-current="true"` on the active one, not ARIA tab roles.
- Item: `-mb-px border-b-2 px-3 py-1 text-sm`. Active: `border-neutral-900 font-medium text-neutral-900 dark:border-neutral-100 dark:text-neutral-100`. Inactive: `border-transparent text-neutral-600 hover:text-neutral-900 hover:underline dark:text-neutral-400 dark:hover:text-neutral-100`.
- All three tabs always render, even when a situation has no data (the content area then shows the empty copy).
- Opening from a Last game unit table lands on that table's situation (D-22).

### Close (D-04)

`PendingLink` `<span aria-hidden>×</span> Close player detail`, `text-sm text-neutral-500 hover:underline`, `aria-label="Close {name} detail"`, `scroll={false}`, href = the current URL without `player` and `all` (keeps `team`, `games`, `sort`, `dir`, `sit`). Placed in the header row, top right.

### Heat-strip cells and popover (D-07)

- Each cell is a `ToiStripCell` (reuse, with the changes under "WR-10" below) with the Phase 1 class list: `group/cell relative cursor-pointer block h-5 w-5 rounded-xs border outline-offset-2 hover:outline hover:outline-1 hover:outline-neutral-400 focus-visible:outline focus-visible:outline-2 focus-visible:outline-neutral-900 dark:focus-visible:outline-neutral-100`, then the state classes from the Color table. Squares are shade-only: no digits inside.
- Popover: byte-identical class string to Phase 1's (`pointer-events-none absolute right-0 top-full z-10 mt-1 hidden w-max max-w-xs rounded-md border ... group-hover/cell:block group-focus-visible/cell:block group-data-[open]/cell:block ...`). Opens below the square, right-aligned, takes no pointer events. The planner may extract the popover span into a shared server component used by `ToiGameStrip` and the new strip; the rendered classes must not drift.
- Popover content, the same `grid grid-cols-[auto_auto] gap-x-3` two-column layout (labels `text-neutral-600 dark:text-neutral-400`, values `tabular-nums text-right`):
  1. Line 1 (`col-span-2 font-medium`): the linemate's name.
  2. Line 2 (`col-span-2 text-neutral-600 dark:text-neutral-400`): `Oct 8 vs TOR · W 3–2` from `formatDate` / `gameLabel` / `resultLabel` (result omitted if not final). OT/SO: append the bordered `rounded border border-sky-500 px-1` `OT`/`SO` tag.
  3. `together` and `apart`: rows `Together` `4:12`; `Share of EV time` `38%`; `Player's EV time` `11:05` (the situation label follows the active tab). OT game: a muted row `OT excluded` is **not** shown (linemate time is regulation only for every game, D-19); instead the OT tag and legend carry it.
  4. `absent`: one muted full-width note: `{Linemate} did not play for {TEAM}`, or `{Name} did not play` when the selected player missed it, or `{Name} had no {EV} time this game` when his situation seconds are 0. (D-20's "not with team" and a scratch share this wording and the same dashed square.)
  5. `unknown`: muted note `No shift chart for this game` and `Left out of shares and tags`.
- The `aria-label` is the same facts as one sentence, built by the same function as the popover rows (one `detailText`-style source, test target). The popover is `aria-hidden`.

### WR-10: expected behavior for the shared square (decision)

The heat strip reuses `ToiStripCell`, so the open WR-10 finding applies to both strips. Contract:
- **Preferred (do once, in `ToiStripCell`, for Phase 1 and Phase 2 strips):**
  - Mouse hover and keyboard focus-visible show the popover; click, Enter and Space **pin** it (`data-open`); a second click/Enter/Space, an outside pointerdown, or blur unpins it.
  - **Escape hides the popover without moving focus** (WCAG 1.4.13): set a `data-dismissed` flag that overrides hover/focus (`group-data-[dismissed]/cell:hidden`), cleared on blur, pointer leave, or the next click/Enter/Space. Remove the current `e.currentTarget.blur()` so keyboard users keep their place in the strip.
  - Remove `aria-expanded`. The popover is `aria-hidden` and its text is already the cell's `aria-label`, so an expanded state would announce a disclosure assistive tech cannot reach, and it disagrees with hover/focus anyway. Keep `role="button"`, `tabIndex={0}` and `aria-label`.
  - Add the new transitions (`dismiss`, reset) to the pure, already-tested `nextOpen`-style function so WR-10 has a unit test.
- **Acceptable fallback:** if the planner defers WR-10, the heat strip must behave exactly like the Phase 1 strip today (no divergence between the two strips), and the deferral stays recorded in 01-REVIEW-DISPOSITION.md.
- Tab stops: a full capped panel adds up to 200 more `tabIndex={0}` squares ahead of the trends table in DOM order. Accepted under the Phase 1 IN-08 decision for a laptop/mouse user; the tabs and close link come first in the panel so a keyboard user reaches them before the squares. Revisit with roving focus only if it proves annoying.

### Show all (D-11)

Below the table, when the list is capped: `<p className="text-xs text-neutral-500">Showing {shown} of {total} linemates, most recent time together first. <PendingLink>Show all {total}</PendingLink></p>`; with `all=1`: `Showing all {total} linemates. <PendingLink>Show fewer</PendingLink>`. The link is `text-xs underline`, `scroll={false}`. Omitted when nothing is hidden.

### Tags (D-14..D-18, PLYR-04)

Rendered in the Tag column as a chip: `inline-block rounded border px-1 text-xs whitespace-nowrap`. Each carries a `title` with the one-line meaning. Decorative glyphs are `aria-hidden`; the word carries the meaning.

| Tag | Chip classes | Glyph | `title` |
|-----|--------------|-------|---------|
| New | `border-neutral-900 bg-neutral-900 text-white dark:border-neutral-100 dark:bg-neutral-100 dark:text-neutral-900` | none | `Little or no time together before the recent games` |
| Rising | `border-neutral-400 text-neutral-900 dark:border-neutral-500 dark:text-neutral-100` | `▲ ` | `Share of {Name}'s {EV} time is up 15 or more points in the recent games` |
| Fading | same as Rising | `▼ ` | `Share of {Name}'s {EV} time is down 15 or more points in the recent games` |
| Out | `border-dashed border-neutral-400 text-neutral-600 dark:border-neutral-600 dark:text-neutral-400` | none | `Missed the recent games` |

- **New** is the only solid chip, so a line change reads at a glance together with recent-first ordering (new linemates rise to the top).
- No tag when the change is under 15 points, or tags are unavailable (see States). The cell is empty, not `—`.
- Rising/Fading use the same ±15 share points as the Phase 1 PP-share movers (D-16); tags never use green or red.

## States

| State | Rule | Visual |
|-------|------|--------|
| No selection | `?player` absent or not digits | No panel; page unchanged. Trends rows have no selected bar. |
| Player not in window | `player` is digits but not a skater who dressed for this team in this window (e.g. after switching to Last game) | In the panel slot: `<p className="text-sm text-neutral-500">` `That player didn't play for {TEAM} in this window.` plus a `Close` link (clears `player`). No header or tabs. |
| Window of 1 | D-15 | Header Δ stats and the Tag column are absent; one square per row; footnote `Tags need 2 or more games. Choose Last 3 or more.` |
| Tags unavailable | The player played fewer than 2 games in the window (D-15), or missed every recent game (D-18) | Tag column stays, cells empty; footnote names the reason (copy below). |
| Selected player missed games | D-18 | His missed games render every row's square as `absent`; excluded from share and tags; legend explains dashed. |
| Linemate missed recent games | D-17 | Tag `Out`; his missed squares are `absent`, never hollow or 0. |
| Linemate not on the team in some games | D-20 | Those squares are `absent`; not counted in his share or tags; if he got real time recently he is `New`. |
| Game without shift chart | D-24 | Every square in that column is `unknown`; amber footnote lists the dates; excluded from share and tags. |
| All games lack charts | No game in the window has a chart | Replace the table with the no-data message (copy below); tabs stay. |
