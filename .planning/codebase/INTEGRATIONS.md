# External Integrations

**Analysis Date:** 2026-10-11

## APIs & External Services

**Discord OAuth:**
- Service: Discord app authentication (https://discord.com/developers/applications)
- What it's used for: User login and session establishment
- SDK/Client: next-auth provider (configured in `auth.ts`)
- Auth: Environment variables `AUTH_DISCORD_ID` and `AUTH_DISCORD_SECRET`
- Callback: Registered redirect URI is `http://localhost:3000/api/auth/callback/discord` (configurable by deployment origin)
- Handler: `app/api/auth/[...nextauth]/route.ts` (delegates to `auth.ts`)

**Fantrax Fantasy API:**
- Service: Fantrax league, roster, and projection data (https://www.fantrax.com/)
- What it's used for: Fetching league settings, team rosters, projections, and player information
- Client: Custom HTTP client in `lib/fantrax/client.ts`
- Endpoints:
  - **fxea** (external API): No authentication required; serves league info, rosters, player pool, standings, draft results, ADP
    - Base: `https://www.fantrax.com/fxea/general`
    - Used by: League import, rosters, player matching
  - **fxpa** (web app API): No authentication required; serves team-specific projections and lineup info
    - Base: `https://www.fantrax.com/fxpa/req`
    - Used by: Per-game projections for planner (in `lib/fantrax/projections.ts` and `lib/planner/sources/fantrax.ts`)
- Auth: None (public endpoints, even for private leagues per verification 2026-09-06)

**Yahoo Fantasy API:**
- Service: Yahoo Fantasy Sports league import (https://developer.yahoo.com/apps/)
- What it's used for: Import league metadata and optionally league rosters via OAuth
- OAuth endpoints:
  - Authorization: `https://api.login.yahoo.com/oauth2/request_auth`
  - Token: `https://api.login.yahoo.com/oauth2/get_token`
- Scope: `fspt-r` (Fantasy Sports read permission)
- Auth: Environment variables `YAHOO_CLIENT_ID` and optional `YAHOO_CLIENT_SECRET` (public PKCE-only apps omit secret; confidential apps include it)
- Callback: `YAHOO_REDIRECT_URI` environment variable (defaults to `https://{origin}/api/yahoo/callback` if not set; http://localhost rejected by Yahoo, use tunnel for local dev)
- Implementation: `lib/yahoo/oauth.ts` (PKCE flow with early token refresh; stored in database via `yahooConnections` table in `lib/db/schema.ts`)
- Routes:
  - `app/api/yahoo/connect/route.ts` - Initiates OAuth flow
  - `app/api/yahoo/callback/route.ts` - Handles callback and saves token

**NHL API:**
- Service: National Hockey League schedule and game data (public, undocumented but stable)
- What it's used for: Current season game schedule for lineup lock periods and matchup analysis
- Base: `https://api-web.nhle.com/v1`
- Client: `lib/nhl/client.ts`
- Endpoints:
  - `/club-schedule-season/{team}/{season}` - Full team schedule for a season
  - `https://api.nhle.com/stats/rest/en/shiftcharts?cayenneExp=gameId={gameId}` - Shift charts for advanced analysis
- Auth: None (public API)
- Implementation note: See https://github.com/Zmalski/NHL-API-Reference for community documentation

## Data Storage

**Databases:**
- PostgreSQL (Neon serverless)
  - Connection: `DATABASE_URL` environment variable
  - Client: `@neondatabase/serverless` via Drizzle ORM
  - Schema: `lib/db/schema.ts` (Drizzle table definitions)
  - Tables: Standard next-auth tables (users, accounts, sessions, verificationTokens) plus custom tables for yahooConnections and league/team data
  - Migrations: Generated by `drizzle-kit generate`; applied via `npm run db:apply`

**File Storage:**
- Local filesystem only
- Projection imports: Temporary Excel files parsed in-memory via exceljs; no persistent file storage

**Caching:**
- In-memory via JavaScript runtime (cached projections have a 24-hour TTL, keyed by day's roster; invalidated by league actions)
- Fantrax projections: Custom cache in `lib/fantrax/cached-projections.ts` with cache tag system

## Authentication & Identity

**Auth Provider:**
- Next-auth 5.0.0-beta.32 with Discord provider
- Implementation: `auth.ts` (configuration) and `app/api/auth/[...nextauth]/route.ts` (handler)
- Session strategy: Database (persistent sessions stored in `sessions` table)
- Session callback: Adds user ID to session for client-side use
- Sign-in page: `/login` (customizable, served by Next.js)

**Account Storage:**
- Provider: Discord
- Tables: `users`, `accounts`, `sessions`, `verificationTokens` (all managed by @auth/drizzle-adapter)

## Environment Configuration

**Required env vars:**
- `DATABASE_URL` - Neon PostgreSQL connection string (required)
- `AUTH_DISCORD_ID` - Discord app ID for OAuth (required)
- `AUTH_DISCORD_SECRET` - Discord app secret for OAuth (required)
- `AUTH_SECRET` - Auth.js session encryption secret; generate with `openssl rand -base64 33` (required)
- `YAHOO_CLIENT_ID` - Yahoo Fantasy app client ID (optional, only for league import feature)
- `YAHOO_CLIENT_SECRET` - Yahoo Fantasy app secret (optional, only if using confidential/"private" Yahoo app)
- `YAHOO_REDIRECT_URI` - Override Yahoo callback URI (optional; defaults to `https://{origin}/api/yahoo/callback`)

**Secrets location:**
- Development: `.env.local` (committed to `.gitignore`, never in git)
- Production: Vercel environment variables
- Local template: `.env.example`

## Data Flow Summary

1. **User Login**: Browser → Discord OAuth → `app/api/auth/[...nextauth]` → Session stored in database
2. **League Import**: User connects Yahoo → `app/api/yahoo/connect` (initiates PKCE flow) → Yahoo OAuth → `app/api/yahoo/callback` (saves token) → Fetch league data from Yahoo API
3. **Fantrax League Load**: User imports Fantrax league → `lib/fantrax/client.ts` fetches league info, rosters, player pool from fxea (no auth)
4. **Projections**: Planner requests projections → `lib/fantrax/projections.ts` fetches from fxpa (cached per roster day) + NHL schedule from `lib/nhl/client.ts`
5. **Database Persistence**: All user, league, and OAuth token data persisted in Neon PostgreSQL via Drizzle ORM
